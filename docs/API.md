# API

Один порт, без внешних зависимостей, JSON на входе и на выходе. Статика
раздаётся с того же адреса, поэтому `http://localhost:8000` — это и интерфейс,
и API.

Все ответы об ошибках имеют одну форму:

```json
{"error": {
  "code": 400,
  "message": "Площадь контура 1791.990 км² превышает предел 20.0 км²",
  "status": {
    "code": "AOI_TOO_LARGE",
    "message": "Площадь контура 1791.990 км² превышает предел 20.0 км²",
    "context": {"area_km2": 1791.989523866254}
  }
}}
```

`error.code` — HTTP-статус, `error.status.code` — машинный код предметной
области, `message` — та же формулировка, что видит пользователь, на русском.
`context` несёт числа, по которым видно, насколько запрос промахнулся.
Полный список кодов — `src/canopy/core/status.py`.

---

## GET /api/health

Сервис жив, и что у него в каталоге: продукты, число файлов, годы,
происхождение (`dataset` или `fixture`).

## GET /api/aois

Готовые участки, сгруппированные по регионам: `aoi_id`, название, роль в кейсе,
площадь, годы, bbox, геометрия. Это удобные заготовки для демонстрации, а не
ограничение сервиса, и в ответе есть `note`, который так и говорит.

## GET /api/sources

Источники данных: идентификатор, название, версия продукта, дата выпуска,
пространственная опора, что источник имеет право утверждать.

## GET /api/config

Лимиты (`config/limits.json`), методы и пороги (`config/methods.json`),
углеродные параметры из `parameters.csv`. Интерфейс берёт отсюда пределы полей и
подписи, так что изменение конфигурации меняет и сервис, и подсказки.

## GET /api/demo

Демонстрационные сценарии. Каждый содержит только то, что пользователь мог бы
ввести сам: геометрию и период. Сохранённых результатов в них нет — и это
проверяется тестом.

## POST /api/readiness

```json
{"geometry": {...GeoJSON...}, "year_start": 2019, "year_end": 2024}
```

Отвечает **до** расчёта: по каждому продукту статус (`AVAILABLE` / `PARTIAL` /
`UNAVAILABLE`), доля покрытия контура, период, число файлов, версия,
происхождение; плюс `blocked` — что именно не будет посчитано и почему, и
`warnings` — что будет посчитано, но с оговоркой.

## POST /api/analyses

```json
{"geometry": {...}, "year_start": 2019, "year_end": 2024, "label": "необязательно"}
```

Принимает `Feature`, `FeatureCollection`, `Polygon` или `MultiPolygon`.
Возвращает `{"analysis_id": "...", "state": "queued"}`. Расчёт идёт в фоне.

Отказы на этом шаге: `INVALID_GEOMETRY` (самопересечение, мало вершин, вершин
больше предела), `AOI_TOO_LARGE`, `AOI_TOO_SMALL`, `INVALID_PERIOD`.

## GET /api/analyses/{id}

Состояние (`queued` / `running` / `done` / `failed`), текущая стадия и доля
выполнения, а по завершении — весь результат:

| Раздел | Что внутри |
|---|---|
| `status` | код и формулировка итога |
| `readiness` | та же готовность данных, зафиксированная на момент расчёта |
| `geometry` | площадь, bbox, сетка анализа, статистика весов пикселей |
| `carbon` | состояния, ΔC, E, e, площади и пропуски, пул, знак |
| `change` | очаги, сцены, окна, рассеянный остаток |
| `uncertainty` | σ(E), L, U, H, слои, сценарии, сверка с ESA, VRI |
| `baseline` | E_base по частям и вариант базовой линии |
| `units` | R, H, H/R, UNC, R_adj, B, Q, остаток, дисклеймер |
| `evidence` | улики, ступени, матрица компетенций, дело |
| `ledger` | узлы происхождения |
| `provenance` | одна строка происхождения на каждое ключевое число |
| `manifest` | входные файлы с sha256, параметры, команда воспроизведения |
| `grid` | данные для карты |
| `warnings` | всё, что пользователь должен знать о результате |

Стадии прогресса: `VALIDATING` → `SEARCHING DATA` → `PROCESSING RASTERS` →
`CALCULATING CARBON` → `DETECTING CHANGES` → `BUILDING EVIDENCE` →
`CALCULATING UNCERTAINTY` → `CALCULATING UNITS` → `READY`. Список приходит в
ответе на `POST /api/analyses`, так что интерфейс не держит его копию.

## GET /api/analyses/{id}/ledger[?trace=НОД]

Весь журнал или дерево происхождения одного узла: значение → формула →
подстановка → входы → файл, sha256, канал, окно. Кнопка **почему** в интерфейсе
вызывает именно это.

## GET /api/analyses/{id}/manifest

Список входных файлов с контрольными суммами, параметры, версия кода и команда
для воспроизведения.

## GET /api/analyses/{id}/changes

Очаги изменений как GeoJSON `FeatureCollection` — чтобы результат можно было
открыть в чужом ГИС.

## GET /api/analyses/{id}/report[?format=html|json]

Самодостаточный HTML-отчёт одним файлом (или тот же результат в JSON).

## POST /api/analyses/{id}/replay

Повторяет расчёт по сохранённому манифесту, предварительно сверив sha256 каждого
входного файла, и возвращает построчное сравнение величин. То же самое из
командной строки: `python3 -m canopy.cli replay <id>`.

## GET /api/analyses

Список выполненных анализов: идентификатор, время, контур, период, статус.
